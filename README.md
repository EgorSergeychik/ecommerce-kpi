# Лабораторна робота №0: Підготовка застосунку — Readiness & Standardization

Цей репозиторій містить виконання лабораторної роботи зі стандартизації застосунку до рівня "Commerce-Ready". Застосунок розроблено на базі фреймворку Laravel 12 (PHP 8). Для роботи було додано кілька моделей та відповідні ендпоінти.

## Фаза 1: Обов'язкові вимоги

### 1. Збірка однією командою (One-Command Build)
Фреймворк автоматично генерує `composer.json` для бекенд-залежностей.
![project structure](https://i.imgur.com/nWzdBDO.png)

Запуск тестів здійснюється однією стандартною командою: `php artisan test` (або `sail test` при використанні Docker-середовища).

### 2. Конфігурація через середовище (12-Factor App)
Усі налаштування застосунку винесені у змінні оточення та зчитуються з файлу `.env`. Для підключення до бази даних MySQL використовуються наступні обов'язкові змінні:
- `DB_HOST=mysql`
- `DB_PORT=3306`
- `DB_DATABASE=example_app`
- `DB_USERNAME=sail`
- `DB_PASSWORD=password`

### 3. Автоматичне керування схемою БД
Механізм міграцій інтегровано в процес запуску.
Для автоматичного застосування міграцій створено скрипт `entrypoint.sh`. Під час запуску застосунок автоматично перевіряє та застосовує всі наявні міграції до бази даних командою `php artisan migrate --force`.

## Фаза 2: Production-Grade фічі

### 1. "Глибока" перевірка стану (Dependency-Aware Health Checks)
Реалізовано ендпоінт `GET /api/health.
Застосунок намагається встановити з'єднання з базою даних через `\DB::connection()->getPdo()`.

* **200 OK:** Повертається, якщо застосунок працює та може успішно з'єднатися з базою даних. У відповіді міститься JSON: `{"status": "success", "data": {"database": true}}`.
  ![health check success](https://i.imgur.com/SME3xct.png)
* **503 Service Unavailable:** Повертається, якщо застосунок працює, але база даних недоступна. Відповідь: `{"status": "error", "data": {"database": false}}`.
  ![health check fail](https://i.imgur.com/Kac01jP.png)

### 2. Структуроване логування в JSON
Для забезпечення сумісності з системами збору логів налаштовано вивід у форматі об'єктів JSON у STDOUT.
Оскільки стандартний `JsonFormatter` Monolog використовує інші ключі, було створено кастомний `App\Logging\JsonFormatter`, який гарантує наявність обов'язкових полів: `timestamp`, `level`, `message`.

**Приклад логів під час запуск:**
![logs](https://i.imgur.com/Zv2rpi6.jpeg)

### 3. Плавне завершення роботи (Graceful Shutdown)
Застосунок налаштовано на обробку сигналу `SIGTERM`.
Для реалізації постійного середовища виконання та коректної зупинки використовується Laravel Octane (сервер FrankenPHP).
Перехоплення сигналу реалізовано на рівні Bash у файлі `entrypoint.sh` (через trap), який виконує наступні кроки:
1. Виводить лог: SIGTERM received. Starting graceful shutdown....
2. Передає сигнал серверу FrankenPHP, який дочікується завершення поточних HTTP-запитів та закриває з'єднання з базою даних.
3. Завершує роботу з кодом 0.
